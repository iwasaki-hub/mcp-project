GITHUB ACTIONS / LEARNING GUIDE

GitHub Actions
YAML入門

いつ、どの環境で、何を実行するか。実際のmcp-projectのワークフローを参考に、YAMLの基本を学びます。

01 / STRUCTURE

ファイルの場所と基本形

ワークフローは .github/workflows/test.yml のような場所に保存します。

name: My First Action

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Get source code
        uses: actions/checkout@v4
      - name: Say hello
        run: echo "Hello GitHub Actions!"

この例はmainへのPush、mainを対象とするPRで実行されます。外部Actionのバージョンは実際の利用時に確認してください。

02 / KEYWORDS

重要なキーワード

キーワード役割
nameActions画面に表示する名前
on実行のきっかけ
jobs処理のまとまり
runs-onUbuntuなどの実行環境
steps処理を実行する順序
uses既存Actionを利用
runシェルコマンドを実行

uses は既存のActionを呼び出し、run はコマンドを実行します。

03 / TRIGGERS

実行タイミングを指定する

PRで実行

on:
  pull_request:
    branches: [main]

mainへのPushで実行

on:
  push:
    branches: [main]

手動実行

on:
  workflow_dispatch:

毎日定期実行

on:
  schedule:
    - cron: '0 0 * * *'

UTC 00:00（日本時間9:00）の指定です。開始は遅延することがあります。

04 / PRACTICE

HTML確認とArtifact保存の例

HTMLの存在をチェックして結果ファイルを保存する小さな例です。HTML構文や内部リンクの検証は行いません。

name: Validate GitHub Pages

on:
  pull_request:
    paths:
      - "docs/**"
  workflow_dispatch:

permissions:
  contents: read

jobs:
  validate:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Check HTML files
        run: |
          mkdir -p reports
          if test -f docs/index.html; then
            echo "HTML check passed" > reports/result.txt
          else
            echo "HTML check failed" > reports/result.txt
            exit 1
          fi
      - name: Upload report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: html-check-report
          path: reports/result.txt
          retention-days: 1

if: always() は前のチェックが失敗してもアップロードを試みます。retention-days: 1 は1日間の保持指定です。

05 / TIPS

書くときの注意

  • インデントはスペース（通常2つ）を使い、タブを使わない。
  • - はリストの項目、| は複数行文字列を表す。
  • トークンやパスワードをYAMLに直接記載しない。
  • permissions は必要最小限にする。
  • 外部Actionのバージョンを確認し、本番ではコミットSHA固定も検討する。
